# 翻译辅助上下文（`work/`）—— 文件清单与记录模板

> **本文回答**：`work/` 里有哪些文件、每条记录该怎么写。
> **本文不回答**：能不能写、冲突怎么处理（→ [`../AGENTS.md`](../AGENTS.md)）。

`work/` 位于 `.translate/work/`，是跨 part 的翻译辅助上下文。
它不是给用户读的小说正文，也不是独立的知识库系统，
唯一作用是让第 100 个 part 的译法和第 1 个 part 保持一致。

**读取原则**：按关键词检索与本 part 相关的条目，**不全量读取**。

## 文件清单

| 文件 | 内容 |
| --- | --- |
| `characters.md` | 人物：日文名 / 中文名 / 性别 / 身份 / 关系 / 说话风格 |
| `terms.md` | 术语表：日文 / 中文 / 备注 |
| `locations.md` | 地点与建筑 |
| `relationships.md` | 人物关系 |
| `timeline.md` | 时间线 |
| `facts.md` | 客观事实 |
| `conflicts.md` | 冲突登记 |

这 7 个文件由 `resume.py init` 创建骨架，之后**只追加、不覆写**。

---

## `characters.md`

```markdown
## 山田太郎

- 日文名：山田太郎
- 中文名：山田太郎
- 性别：男（原文明确）
- 身份：……
- 与其他人物关系：……
- 说话特点：……
- 已确认事实：……
```

只记录**原文已经明确**的信息：性别仅在原文明确时才记，不记推测。

## `terms.md`

```markdown
| 日文 | 中文 | 备注 |
| --- | --- | --- |
| XXX | XXX | …… |
```

遇到相同术语优先沿用已定译法。若发现之前的译法可能有误：

1. 回查原文上下文
2. 把冲突登记进 `conflicts.md`，**暂停等待人工确认**
3. 人工确认后再更新术语表
4. 必要时走重译流程统一修正，不要直接改文件

## `locations.md`

记录后续可能需要引用的空间信息：某人住在哪、某建筑有什么房间、某物品在哪里出现过。

## `relationships.md`

记录人物之间的关系（亲属、上下级、师徒、恋人等），以及关系在文中的变化节点。

## `timeline.md`

```markdown
- 第 3 章 / 4 月 5 日：某事件发生
- 第 7 章 / 三年后：……
```

仅记录原文明确给出的时间信息，不推算。

## `facts.md`

客观事实，非推测。例如「某人已知道某事」「某物已被谁拿走」。

## `conflicts.md`

```markdown
## part_012

- 原条目：characters.md —— 山田太郎 / 性别：男
- 新发现：part_012 原文出现「彼女」
- 冲突原因：原文此前未明确性别，此处首次出现性别指代
- 建议处理：回查 part_003 上下文后确认
```

冲突**不自动修改**，暂停等待人工确认。
