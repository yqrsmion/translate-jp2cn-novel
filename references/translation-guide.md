# 翻译执行规范（Translation Guide）

本文件是 `translate-novel` 的**翻译行为准则与工程约束**，供执行翻译的 Agent 参考。

- 执行步骤与命令：见 `SKILL.md`（本文件由它引用，不再向下引用其它 reference）

---

## 1. 定位与任务

你是一名小说翻译 Agent。任务：把一本小说**完整**翻译成自然、准确、连贯的目标语言。

工作方式是**持续推进的翻译项目**，不是一次性翻译：每完成一个 part，译文与新发现的客观事实都会成为后续工作的基础。

本规范面向**长篇文学作品的整本翻译**（非摘要、非节选）。不做短句翻译，不做译后润色出版。

## 2. 核心目标

1. 忠实翻译原文，不擅自改写剧情
2. 目标语言表达自然，不机械直译
3. 保持人物说话方式、语气、性格的一致性
4. 人名、地名、组织名、专有名词保持统一
5. 不遗漏原文内容
6. 不提前补充后文信息
7. 不主动分析、推理、猜测剧情走向
8. 原文有歧义时保留原意，不擅自脑补

## 3. 最重要的原则

优先级：

**准确性 > 一致性 > 自然度 > 翻译速度**

无法确定时：**查原文和已有资料，不要猜。**

## 4. 执行流程

```text
读取原文
  ↓
确定当前翻译范围
  ↓
检索相关翻译辅助上下文
  ↓
翻译
  ↓
检查一致性
  ↓
提取新的客观事实
  ↓
追加进 work/
  ↓
保存译文
  ↓
继续下一个 part
```

不要一次性把整本小说放进上下文。

## 5. 输入文档定位

源文档按以下优先级确定：

1. 用户在提示词中显式指定的文档（最高优先级）
2. `--source <路径>` 命令行参数
3. 环境变量 `NOVEL_SOURCE`
4. 当前工作目录下**唯一的** `*.txt`
5. 存在多个 `*.txt` → **停止并请用户指定，绝不猜测**

## 6. 输出命名

最终译文用**目标语言书名**命名（不用原标题后缀）：

| 产物 | 命名 | 源 `<原标题>.txt` 时 |
| --- | --- | --- |
| 译名与原名不同 | `<目标语言书名>.txt` | `<目标语言标题>.txt` |
| 译名与原名相同 / 未取到译名 | `<原名>_translated.txt` | `<原标题>_translated.txt` |

- **目标语言书名** = 把源文件名（原标题）翻译一遍。配了 `NOVEL_LLM_*` 时脚本自己译；
  没配就由你译出后经 `merge.py --title "目标语言书名"` 传入（写入 `state.json` 的 `output.title_cn`）
- **卷次、作者保留**，只清掉下载站后缀之类的脏数据；书名用**目标语言**

  ```text
  源：世界の終りとハードボイルド・ワンダーランド 上 (村上春樹) (z-library.sk, 1lib.sk, z-lib.sk).txt
  产物：世界尽头与冷酷仙境 上 (村上春树).txt
  ```
- **译名与原名相同**（或没取到译名）时才用回退名 `<原名>_translated.txt`
- 译文与源文档**同一级目录**

**禁止**自己创建、重命名最终译文文件——文件名由 `merge.py` 决定并写入。

## 7. Translation Workspace

运行某一本小说时，在**源文档所在目录**（`ROOT`）建立独立工作区：

```text
ROOT/
├── <原标题>.txt               原文（唯一权威，只读）
├── <目标语言书名>.txt         最终译文（回退时为 <原标题>_translated.txt）
│
└── .translate/               可恢复的工作状态
    ├── parts/                原文分片
    ├── parts_out/            逐 part 译文
    ├── work/                 翻译辅助上下文
    ├── incoming/             未提交的暂存草稿
    ├── archive/              重译时归档的旧译文
    ├── manifest.json         切分清单
    └── state.json            进度状态
```

要点：

- Skill 目录不保存任何小说状态，工作区永远跟着源文档走
- 中间态默认保留，用于断点恢复、排错、重新校验、重新合并
- 最终交付物只有一个 `.txt`：`<目标语言书名>.txt`（回退时为 `<原名>_translated.txt`）
- 需要清理时直接删除 `.translate/`；删除后无法再断点恢复或重新合并

## 8. 文件操作白名单

| 权限 | 路径 |
| --- | --- |
| 允许读 | 源文档、`.translate/parts/part_XXX.txt`、`.translate/manifest.json`、`.translate/state.json`、`.translate/work/*.md` |
| 允许写 | `.translate/parts_out/part_XXX.txt`、`.translate/work/*.md`（仅追加） |
| 禁止写 | 源文档、最终译文、`.translate/parts/`、`manifest.json`、`state.json` —— 均由脚本维护 |
| 禁止 | 创建 / 删除 / 重命名 / 移动白名单外任何文件 |

`state.json` **可以读，禁止写**。所有状态变更必须通过脚本完成。

## 9. 唯一数据源

- 源文档是唯一权威原文。禁止以 `parts/`、`parts_out/`、`incoming/` 或任何其它派生文件作为翻译依据
- 所有切分、校验、恢复均以源文档的字符偏移量为准

## 10. 切分规则

- 切分只在初始化时执行一次，生成 `.translate/parts/` 与 `manifest.json`
- 切分后禁止重切分、追加切分或修改 part 内容
- 切分出错只能删除整个 `.translate/parts/` 后重跑切分
- **绝不切断段落**：只允许在空行 / 章节 / 句末等安全边界切

## 11. 状态机

每个 part 的 `status` 取值为 `PENDING` / `IN_PROGRESS` / `FAILED` / `DONE`，
"待人工复核"由 `needs_human_review` 标记表达。

- 严格按 `manifest.json` 顺序线性推进，**禁止跳过、并行、逆序**
- 禁止重复翻译已完成的 part
- 每个 part 完成必须原子推进：译文落盘 → 校验通过 → 状态置 DONE

## 12. 单 part 原子翻译

- 每次只翻译一个 part，输入：`part_id` + part 原文 + 相关 `work/` 片段
- 输出**只有译文文本**，不含元数据、解释、进度标记
- 译文行数必须严格等于原文非空行数（一行对一段）
- 译文字符数异常只是信号，不是判据：整 part 级 `<0.6x` / `>2.5x` 仅告警；
  段落级超出 `0.30` / `2.50` 会判 FAIL 并阻断

## 13. 完成判定

- 你**绝不判断**"是否翻译完""是否到结局""是否可以停止"
- 唯一判据：所有 part 均为 `DONE` 且 `state.json.current_part_id == null`
- 遇到「完」「终」「THE END」「完结」等词汇，仅正常翻译，不做任何控制流决策

## 14. 上下文管理

- 不要试图一次性把整本小说放进上下文
- 按自然结构推进：章节 → 小节 → 段落
- 每 part 只处理当前范围，附加前一片的译文尾部与原文尾部

## 15. 翻译风格

采用**忠实原文 + 自然目标语言**，而不是逐字直译。原文表达直译生硬时可重排语序，但：

- 不改变事实
- 不改变人物关系
- 不改变语气
- 不改变信息量
- 不增加原文不存在的信息

**保留原文暧昧**：原文省略主语、未标性别、指代模糊时，不要替作者把话说清楚。

## 16. 对话

保持人物个性区分：

- 语体差异（敬语 / 口语 / 书面语等，依源语言而定）
- 年龄差 / 上下级 / 亲疏关系
- 特定口头禅、句尾特征

不要把所有人物译成同一种说话方式。

## 17. 不确定时的处理

遇到以下情况必须主动回查原文与 `work/`：

- 人物指代不明确（"他 / 她 / 那个人"指谁）
- 某物品之前在哪里出现过
- 某事件发生的时间不明确
- 人物关系可能影响翻译
- 同一个源语言名称存在不同译法
- 某句话存在明显歧义
- 当前内容依赖前文信息

仍然无法确定时：**保留原文的歧义，不擅自增加原文没有的信息。**

## 18. 翻译辅助上下文 `work/`

`work/` 是 Translation Workspace 中的**翻译辅助上下文**，用于维护跨 part 翻译所需的
人物、术语、地点、事件及其他已确认的信息。

- 只保存与翻译质量直接相关的信息
- 文件清单与记录模板见 `knowledge-base.md`（由 `SKILL.md` 引用）

## 19. 人物信息

发现重要人物时记录：源语言原名、目标语言译名、性别（仅原文明确时）、身份、
与其他人物的关系、说话风格、已确认的重要事实。

**不记录未经原文确认的推测。**

## 20. 术语表

发现反复出现的专有名词时记录"源语言 / 目标语言 / 备注"，后续优先沿用已定译法。

若发现之前的译法可能有误：回查原文 → 把冲突登记进 `conflicts.md` 并**暂停等待人工确认**
→ 人工确认后再更新术语表 → 必要时走重译流程统一修正，不要直接改文件。

## 21. 地点与事件

记录后续可能需要引用的信息：某人住在哪、某建筑有什么房间、某事件发生的时间、
某人何时见过谁、某物品在哪里出现过、某人已经知道什么。

只记录原文已明确的信息，不把推理当成事实。

## 22. 译前信息检索

每个 part 翻译前：

1. 阅读当前原文
2. 判断是否依赖前文（人物 / 地点 / 事件 / 术语）
3. 需要时读取 `work/` 中**相关**条目
4. 再开始翻译

按关键词检索，**不全量读取** `work/`。

## 23. 工作上下文冲突处理

- 翻译后仅**追加**本 part 新发现的客观事实
- 发现与既有条目冲突 → 追加进 `work/conflicts.md`
  （含 part_id、原条目、新发现、冲突原因、建议处理）
- **暂停等待人工确认，不自动修改**
- 人工确认后再更新对应条目

## 24. 每章 / 每 part 完成后的检查

1. 检查是否漏译
2. 检查人名是否一致
3. 检查专有名词是否一致
4. 检查人物称呼是否一致
5. 检查时间、地点、事件是否出现明显矛盾
6. 提取本章新发现的客观事实
7. 追加进 `work/`
8. 保存翻译结果
9. 再继续下一章

不要为了"完善上下文"而重新分析整本小说。
